# Требования к портфолио

## Цель

Одностраничный сайт-портфолио, который за 30–60 секунд убеждает работодателя (рекрутера, тимлида, CTO) пригласить кандидата на интервью.
Сайт должен продавать: не пересказывать резюме, а показывать результат, масштаб и сложность решённых задач.

## Целевая аудитория

| Кто                       | Что ищет                                            | Сколько времени тратит |
| ------------------------- | --------------------------------------------------- | ---------------------- |
| Рекрутер                  | Стек, грейд, годы опыта, контакты                   | 10–30 сек              |
| Тимлид / техлид           | Глубину задач, архитектурные решения, качество кода | 2–5 мин                |
| CTO / нанимающий менеджер | Влияние на бизнес, цифры, ответственность           | 1–2 мин                |

Отсюда правило: **каждый блок читается «по слоям»** — заголовок и цифра видны сразу, подробности раскрываются по клику.

## Принятые решения

| Вопрос          | Решение                                                                                                                                                                    |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Целевая позиция | Middle / Middle+ Frontend / Fullstack JS Developer                                                                                                                         |
| Языки           | RU (по умолчанию, `/`) + EN (`/en/`), переключатель в хедере; язык задаётся адресом (ссылку можно отправить на нужной версии), при переключении сохраняется текущая секция |
| Хостинг         | GitHub Pages, автодеплой через GitHub Actions                                                                                                                              |
| Фото            | [`photo.jpg`](../src/content/photo.jpg), закат у залива: палитру сайта строим от него (синий → розовый → оранжевый)                                                        |
| Анимации        | Максимум выразительности, включая 3D (см. ниже)                                                                                                                            |
| Контакты        | email, Telegram, GitHub — телефон не публикуем                                                                                                                             |
| Проекты         | Отдельной секции нет; Keepfit — флагманский кейс в опыте                                                                                                                   |
| Тон текстов     | Сдержанный и практичный, без громких слоганов                                                                                                                              |

## Источник данных

Вся фактическая информация берётся из резюме и ответов владельца; итоговые тексты — в [`src/content`](../src/content). Ничего не выдумывается: если метрики нет в резюме, её спрашивают у кандидата, а не сочиняют.

## Структура страницы

1. **Hero** — имя, роль, короткое практичное описание, ключевые цифры (лет опыта, проектов, пользователей и т.п.), CTA: «Написать в Telegram», «Смотреть опыт». Кнопка «Скачать резюме (PDF)» — после подготовки PDF без телефона.
2. **Обо мне** — 3–5 предложений: кто я, в чём силён, что ищу.
3. **Стек / навыки** — сгруппированный (языки, фреймворки, инфраструктура, инструменты), с визуальным акцентом на основном стеке.
4. **Опыт работы** — таймлайн, по карточке на каждое место работы:
   - компания (логотип, если можно), должность, период, формат;
   - краткое описание продукта и зоны ответственности;
   - ключевые достижения с цифрами;
   - стек на этом месте;
   - **раскрывающийся блок «Сложные задачи»** — 1–3 кейса в формате _Проблема → Решение → Результат_, с техническими подробностями.
5. **Образование / сертификаты** — кратко.
6. **Контакты** — email, Telegram, GitHub, кнопка скачивания PDF-резюме.

## Визуал и UX

- Яркий, современный, запоминающийся дизайн: тёмная тема по умолчанию + светлая, «закатные» градиенты, акцентный цвет.
- **3D в Hero:** интерактивная WebGL-сцена (Three.js), реагирующая на курсор и скролл, например абстрактная «живая» сфера или сетка частиц в палитре заката.
- Анимации появления блоков при скролле, параллакс, микроанимации и 3D-наклон карточек на hover, анимированные счётчики цифр в Hero.
- Таймлайн опыта «прорисовывается» при скролле; кейсы раскрываются плавной анимацией.
- 3D-сцена грузится лениво и не блокирует первую отрисовку. На слабых устройствах и без WebGL вместо неё статичный градиент.
- Анимации уважают `prefers-reduced-motion`.
- Адаптив: от 360px (телефон) до широких мониторов; без горизонтального скролла.
- Навигация: липкий хедер с якорями на секции, подсветка активной секции.
- Доступность: контраст WCAG AA, семантическая разметка, навигация с клавиатуры, `alt` у изображений.

## Нефункциональные требования

- **Производительность:** Lighthouse ≥ 95 по Accessibility, Best Practices, SEO; Performance ≥ 90 (с учётом 3D-сцены).
- **SEO / шаринг:** `<title>`, meta description, Open Graph и Twitter-карточка с превью, favicon, `sitemap.xml`, `robots.txt`.
- **Хостинг:** статический сайт, бесплатный хостинг (GitHub Pages или Vercel), автодеплой из `main`.
- **Контент отделён от кода:** все тексты лежат в типизированных файлах данных — обновить опыт можно, не трогая компоненты.

## Требования к репозиторию

Репозиторий — тоже часть портфолио; его будут открывать. Подробности — в [ENGINEERING.md](./ENGINEERING.md).

Кратко:

- Понятный `README.md` со скриншотом, ссылкой на живой сайт, стеком и инструкцией запуска.
- Строгий TypeScript, ESLint, Prettier, единый стиль.
- Осмысленные коммиты в формате Conventional Commits.
- CI: линт, проверка типов, сборка на каждый push/PR.
- Никаких мусорных файлов в git: IDE-настройки, `.DS_Store`, сборка, `node_modules`.
- **Файлы Claude (`CLAUDE.md`, `.claude/` и т.п.) в git не попадают** — они в `.gitignore`.

## Критерии готовности

- [ ] Все секции заполнены реальными данными из резюме, на RU и EN.
- [ ] Для каждого места работы есть описание и минимум один кейс «сложная задача».
- [ ] Сайт задеплоен и открывается по публичной ссылке.
- [ ] Lighthouse: Performance ≥ 90, остальные ≥ 95 (мобильный профиль).
- [ ] CI зелёный, в репозитории нет лишних файлов.
- [ ] README оформлен, есть скриншот и ссылка на сайт.
